# Drift checks D1–D22 and the base regen rules

> Draft companion to ADR-0020 (Revision 13). Repo path: `docs/agents/drift-checks.md`. Tech Writer revision (2026-10-07, 10 PM ET) of the Architect's draft, which it supersedes; changes are marked **[TW]** and listed in the drafts README.

## Scripts (single files, `node:` builtins only)

- `check-drift.mjs --root <dir> [--paths <tree.json>] [--base <dir>] [--regen]` runs D1–D22.
  - `--root` is the tree under test.
  - `--paths` is the full head tree listing (with blob `sha`), used for the presence, absence, case, mode and link checks.
  - `--base` is the trusted base checkout, used for the comparisons in D10 and D17 and the R3-F4 supersets.
- `generate.mjs [--check] [--root <dir>]` renders the adapters.
- `pr-data.mjs` fetches PR data via the REST API; `governance.mjs` is the governance-paths logic (both in `governance.md`).
- D12 reads line-anchored markers in `claude-review.yml` (`# agents-drift:restore-step:begin|end`, `# agents-drift:claude-args`, `# agents-drift:hook-canary`), not a YAML parse.

## Where each check runs

- **Base job:** every check runs in `agents-drift (base)` on the PR's data. Regen-diff parts (D4, D7 generated `.cursor/hooks.json`, D9 Gen, D10 head part, D11, D14) use main's generator; when the PR changes generator code they switch to the supersets below.
- **Head job:** every check also runs in `agents-generate` with head code.

## Bootstrap arming (rev 5; R4-F1, R4-F2, R4-N9; rev 6: R5-F3, N4–N7, N9; rev 7: N2, H14)

The bootstrap PR puts this checker on `main` before the harness exists. Arming keeps app PRs green until the harness lands, without giving a PR a way to switch a check off.

- **Data, not code (R4-F2):** the always-armed set and the per-check subjects live in `scripts/agents/arming.json`, which is in the blob input set. The base job always uses **main's** copy. **D22** fails a PR whose copy drops an always-armed ID or a subject (PR ⊇ main), and a PR that **deletes** `arming.json` (missing = fail, never "empty"; N5a). DEP-R1 has no bypass actors (H12), so a deliberate shrink merges only through the break-glass procedure (`governance.md`; invariant changes only, H14).
- **Always armed (R4-F1(b)):** D1, D3 (incl. a committed `.claude/settings.local.json`, R5-F3), D4 (invariant parts: manifest-only, root `.cursor/rules/areas/` only, never `alwaysApply: true`), D5, D6, D7, D8, D9 (unique names, `.cursor/agents/` absent), D11 (`.claudeignore` absent), D13, D15, D16, D17, **D18 (all parts, incl. the hook-command allowlist; it has no subject, N4)**, D19, D20, D21, D22 and the presence rule P. These all pass on `main` today (D18's settings parts pass vacuously while no settings file exists, and P stops a deletion), so disarming them would buy nothing.
- **Subject-armed checks** (armed when a subject matches on `main` **or** in the PR):

| Check part | Subject (case-folded glob) |
|---|---|
| D2 stubs | any non-root `**/agents.md` or `**/claude.md` (eight nodes) |
| D4 regen | `.cursor/rules/areas/*.mdc`, or `cursorAreaRules: true` in main's `adapters.json` |
| D7 generated hooks | `.cursor/hooks.json` |

- **Lookups (R4-F1(c)):** every path comparison (subjects, steering-path matches, D3/D19 names) is case-insensitive after NFC normalization. Base presence comes from `git ls-tree -r --name-only <main sha>` in the base checkout; head presence comes from `paths.json` (API tree, `truncated: false`, already fail-closed). **Any lookup error fails the job**: no `existsSync`-style probe that turns EIO or EACCES into "absent".
- **Presence rule P (R4-F1(d)):** a subject present on `main` and absent from the PR **fails** (no vacuous pass). A declared removal merges only through the break-glass procedure (`governance.md`; no bypass actors, H12, H14). This also catches deleting nested `AGENTS.md`/stub pairs and renaming `.claude/settings.json` away.

- **Visibility (R4-N9):** the `agents-drift (base)` step summary lists every disarmed check by ID ("disarmed: D2, D10, …; subject absent on main and PR"). A disarmed check concludes **success with a notice**, never skipped.
- Absent sources render to absent outputs; the superset rule "still exists" applies only to outputs present on `main`.
- **Simulation (N7):** Architect's re-run of CR's `arming_sim.py` scenarios plus CR5's probes N1/N2/N7/N8, `adr-harness-review-artifacts/r9-arming_sim.{py,txt}`: 55 rows, 0 bypasses (MIN_DENY modelled as 6 + 21 + 28 + 14 + 1; rev 9 adds R9c/R9w/R9f/R9g/R9xc/R9xr (each missing rev 9 deny fails), R9ok/R9okc (**[TW] rev 10 drops R9h/R9hc/R9ha/R9hp, the health-script allow rows; the full-set rows move to 71 / 70 in the build work's fixtures**. ## `--regen` in the base job

- **Regenerate-and-diff:** **main's** generator renders `cli.json`, `.cursorignore`, `secret-patterns.txt` and the enabled `.mdc`/`.grok` fallbacks from the **PR's** source files in the scratch tree. The output goes to a second scratch dir and is byte-compared with the PR's committed outputs. PR JSON (`permission-map.json`, `adapters.json`, `settings.json`) is input data only, and output paths come from main's `adapters.json` (R3-N2).
- **"Generator changed"** = the `sha` of `scripts/agents/generate.mjs` in `paths.json` ≠ main's blob sha.

## When the generator changed: base semantic supersets (R3-F4)

A generator PR can change the **format** of an output but never **drop** an entry. Instead of byte-equality, the base job checks every output listed in **main's** `adapters.json`:

| Output | Base superset check (all main code, PR files as data) |
|---|---|
| (all) | Every output path in main's manifest still exists in the PR tree. New outputs are allowed. |
| `.cursor/cli.json` | deny ⊇ main's committed deny (normalized) **and** ⊇ the mapped PR Claude deny (D10, with the H11 exemption for Claude's exact `Bash(git push)`); no `Shell(git:push)`/`Shell(git:push*)` (H7, H11); allow ⊆ main's allow; colon form only. |
| `.cursor/hooks.json` (H8) | byte-equal to main's generator output (one command, `node scripts/agents/hooks/guard.mjs`, on `beforeShellExecution`); never dropped while main has it. |
| `.cursorignore` | non-comment lines ⊇ main's lines **and** ⊇ the set main's mapping derives from the PR's Claude `Read` denies. |
| `scripts/agents/hooks/secret-patterns.txt` | rule ids ⊇ main's ids **and** ⊇ the ids **main's** parser derives from the PR's `.gitleaks.toml`; the pattern for each id equals what main's parser derives for it. |
| `.cursor/rules/areas/*.mdc` | each body (after frontmatter and header) == its nested `AGENTS.md`; frontmatter `alwaysApply: false`, `globs: <area>/**`. |
| `.grok/agents/*.md` | the name set ⊇ `.claude/agents/` names; each body == its source modulo the header. |

- **Every invariant check** (D1–D3; D4's invariant parts: manifest-only, root only, never `alwaysApply: true`; D5–D9; D10 semantic; D11's `.claudeignore`-absent part; D12–D22; P) still runs on the data as well (R4-N6).
- Main's generator also runs anyway, and its diff against the PR's outputs is posted as a **warning** in the step summary (escaped, capped).
- `governance-paths (base)` flags the PR (`scripts/agents/**`), so gate 3 reviews it.
