**`.cursor/cli.json` schema (TR):** project file `<repo>/.cursor/cli.json`, global `~/.cursor/cli-config.json`. "Only permissions can be configured at the project level." Pure JSON. Tokens: `Shell(cmd)` / `Shell(cmd:args)`, `Read(glob)`, `Write(glob)`, `WebFetch(domain)`, `Mcp(server:tool)`. Deny beats allow; no `ask` list. The generator emits only `{"permissions":{"allow":[…],"deny":[…]}}`. Cursor's handling of unknown keys is undocumented (U8), so there is no in-file marker; `generated.lock.json` + D14 instead.

**Cloud agents (U9; H8, Helms 6:25 PM ET):** the official Cursor docs describe `cli.json` only as the **Agent CLI** configuration, and say Cloud Agents "do not use Run Modes" and run hooks from `.cursor/hooks.json` (plus team/enterprise hooks). Condition and fallback: ADR §8. **[TW] Rev 10:** cloud agents push as the **Cursor GitHub App**, not as `llevintza`; the DEP-R1 ruleset applies to the App, and the App must not be on the bypass list.

**Guard under several hook sources and time budget ([TW] rev 10; C7).**
- **Runs at most once per tool call.** Grok Build reads both `.claude/settings.json` hooks and `.cursor/hooks.json` (M§5), and Cursor IDE/CLI may run both the imported Claude hook and the generated `.cursor/hooks.json` entry. The guard is idempotent: it records each decision under a key built from the normalized command or tool input, and a second call for the same tool call returns the recorded decision without re-evaluating. A recorded block is never turned into an allow; a missing or unreadable record means full evaluation. ADR-0020 rev 10 fixes the behaviour (each tool call is recorded once); the key and where the record lives are left to the build work (Architect), and this mechanism is TW's proposal for it.
- **Time budget (G-requirement, rev 10; Residual 11).** The guard must decide in **≤500 ms at p99**, with a **1 s internal hard cap that fails closed** (exit 2, whatever the input shape), well under the smallest harness timeout (Grok's 5 s default, which fails open; M§5). A timing fixture enforces it (`testing.md`), and the generated hook entry sets an explicit `timeout`. Measured on the box: p99 ≈ 10 ms in-process, ≈ 171 ms per fresh-node hook invocation (`r10-timing.txt`). A harness timeout still fails open in Grok: Residual 11 (owners Architect and TC; revisit at the Grok spike or if CI p99 exceeds the budget).

**Guard input handling (H4, Helms decision, R3-F5; push rule R4-M1(c)):**
- **Recognized shapes** are the documented Claude shape, the Cursor-imported shape recorded by the U21 stdin canary, and the Cursor-native `beforeShellExecution` shape (`command`, `cwd`) from the generated `.cursor/hooks.json`. On a recognized shape the guard **fails CLOSED**: a matched rule exits 2, and a malformed payload (e.g. a command tool without a string `command`) exits 2. Unknown tool names in a recognized shape pass (exit 0).
- **Push/merge-shaped input is always recognized:** any payload whose raw text **or JSON-decoded string values** (so `\u` escapes count) match the push/merge/ref-write/admin signature (`git|hub … push|send-pack`, `gh … merge|api`, `git/refs`, `/merge`, `graphql`, `/contents/`, `api.github.com`, and the admin set: `/rulesets`, `/protection`, `default_branch`, `/environments`, `/secrets`, `/variables`, `/dispatches`, `updateRepository`, ruleset and branch-protection mutations, `gh repo edit|delete|rename|archive`, `gh secret|variable set|delete`, `gh workflow run|enable|disable`, `gh run rerun`, `gh alias set`) exits 2 unless it parses as a recognized shape **and** every destination is provably not `main`. **On the recognized path the same rule applies per command segment** (R5-F1 class A): a segment carrying the signature that wasn't analysed and proven exits 2. Exempt: text-only heads (`echo`, `printf`, `grep`, `rg`, `cat` …) unless their output is piped into a shell, git message/read subcommands (`commit`, `tag`, `notes`, `log`, `show`, `grep`, `diff` …), and `gh` commands the gh analysis has already decided (so `gh pr create --body "…git push…"` passes). **Indirect execution (G13):** in a payload carrying the signature, a shell or interpreter run on a file, stdin or `<(…)` (`sh f`, `bash f`, `source f`, `. f`, `./x`, `/path/x`, `python3 x.py`) exits 2, so write-then-run is caught. **G22 (rev 10, R9-M3):** writing or replacing a script or binary and then running it in the same call fails closed in any payload (TOCTOU; CR9 H01, H02, H06 block; the cross-call H03/H04 forms are Residual 4). This stays inside H4 (closed on recognized input).
- **Any guard exception exits 2** (class E); the CLI wrapper also catches. **A tokenizer error** (e.g. an unbalanced quote in a heredoc) **fails closed only when the signature matches** (CR5 D05); `#` comments are ignored (R11).
- **Unrecognized non-push input** (not JSON, or a shape that matches neither, with no push/merge signature) **fails OPEN**: exit 0, one stderr warning `agents guard: unrecognized hook input; not enforcing`, and a redacted one-line record appended to `os.tmpdir()/agents-guard-unrecognized.log`.
- Reason: the guard is best-effort, Cursor already fails open on crash/timeout and the import is user-toggleable; blocking on an unknown shape would brick Cursor sessions and push people to turn the import off. **CI and human review are the enforcement.**
- **Blocking output:** exit 2, a stderr reason, and on stdout `{"permission":"deny","user_message":…}` for the Cursor-native hook (the reply format is UNVERIFIED, U21; exit 2 alone blocks per TR U15).
